# Local artifact to production delivery — PTT

Read [central CI/CD](ci-cd.md) and the selected [release](release.md) record. Route: frozen qualified VSIX → explicitly selected GitHub public release and/or desktop VS Code profile. There is no cloud/server/database deploy. Entry: actual target authority, pushed source, engineering/native release admission, digest/provenance and prior-installer/metadata recovery checkpoint.

1. **Verify source, artifact and target.** Resolve the frozen revision, actual release/installed state and intended repository/profile. Check manifest/version, SHA-256, compiled module bytes and actual native proof. Run `node scripts/quality-gate.cjs check release` after release qualification. Missing native/release evidence blocks publication; CI or private packaging is insufficient.
2. **Check drift and recovery.** Recheck version/target and immutable bytes; retain the previous VSIX/checksum. Back up affected actual metadata before an intentional migration outside source/package. Preserve tmux/agents, other windows and provider auth. If target bytes already match, verify rather than deliver again. No kill-server or credential reset.
3. **Deliver the authorized frozen unit.** For GitHub use `gh release create` with the reserved new tag, `--repo maxtymosh/persistent-terminal-tabs`, full reviewed `--target`, qualified `--notes-file` and frozen VSIX/bundle/prompt/checksums from the release record. Collision holds publication; never overwrite public bytes. For authorized installation use supported `code --install-extension` with the absolute frozen VSIX and selected profile; the macOS CLI is `/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code`. Use normal Restart Extensions and preserve active chats. Marketplace needs its separately verified publisher connection; missing auth never licenses silent browser takeover.
4. **Verify actual delivery.** Read release/tag/asset state; anonymously download public assets, compare digests and nested VSIX/bundle checksums. For installation compare all runtime modules, loaded activation version and before/after pane identities, then required native journeys. Publication, installed bytes, loaded version and accepted behavior are separate results. Recover a verified failure with the supported previous-VSIX route, preserving user data.
5. **Record and return to release.** Save source/target/hashes, recovery and actual checks/blockers in existing release/public history. Commit/push exact delivered source and receipts in the same turn through guarded integration, never raw-push around main rules. Return combined/product acceptance to [release](release.md); do not repeat delivery on stage entry.

Exit: selected actual targets verified with limits explicit. GitHub-only scope grants no Marketplace/install action; install-only scope publishes nothing. Reuse valid authority without redundant prompts. No unsupported staging/cloud step is added.
