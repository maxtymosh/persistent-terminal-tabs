# Release — PTT selected VSIX target

Read [central CI/CD](ci-cd.md). Owns delivery/combined acceptance for frozen merged changes, consuming durable [PR](pr.md)/[merge](merge.md) handoffs. Select actual GitHub public, Marketplace and/or desktop/profile targets. No Beta/Stable rings/cloud exist. PR-only, merge-only and status requests start no release; explicit holds remain holds.

1. **Select target and freeze scope.** Read actual previous release/installed state, main, PRs and release claims. Reserve a new version under one release owner; no concurrent publication/UI driving. Record authority, targets, compatibility and holds; preserve immutable artifacts.
2. **Inventory every included change.** Enumerate all commits, merged PRs, direct commits and squash/rebase equivalents since the previous target revision, not only a PR search. Consume task handoffs and record each change's risk, review/check proof, skips/blockers, compatibility/migrations and required journeys. Exclude unmerged work unless separately qualified. A moving candidate invalidates affected inventory/proof.
3. **Verify the combined candidate.** Derive regression/native journeys from every inclusion and interactions. Run `npm run verify`, affected actual behavior and advisory checks; disposition moderate findings. Individual PR passes alone are insufficient. Reuse unchanged source/runtime proof only with documented equivalence; scale mocks are not native/performance acceptance. Keep old product gaps assigned and explicit.
4. **Prepare immutable native-qualified delivery.** Require exact candidate CI, provenance, identity/version, full module comparison and VSIX digest. Preserve frozen VSIX/bundle outside regenerating output. Run affected [native QA](../../docs/development/native-qa.md), recording actual VS Code/OS, tester, loaded version, before/after session identities and real actions/results. Only then record nativeQA pass and a separate Ship verdict. `npm run release:check` rebuilds `qa-artifacts` before admission: never substitute regenerated bytes for the frozen native-qualified artifact. Recheck the selected frozen digest against native proof, or reopen qualification. No invented signing/cloud/ring gates apply to VSIX.
5. **Integrate required release inputs.** Follow [merge](merge.md) for version/notes/evidence integration. If inputs are already merged, verify that reason rather than creating a dummy PR. Changed inputs/conflicts reopen affected review/CI/build/native proof. Documentation-only changes may reuse runtime equivalence only when recorded and verified; do not claim another artifact was tested.
6. **Deliver through the actual transition.** Invoke [local-prod](local-prod.md) only for authorized missing targets after release admission. [Local-stage](local-stage.md)/[stage-prod](stage-prod.md) are explicitly N/A. Already delivered identical bytes are verified, not delivered twice. GitHub publication does not silently publish Marketplace or replace a desktop profile.
7. **Verify target and combined acceptance.** Check tag/source, anonymous hashes/nested bundle bytes; for authorized install check installed modules, loaded version and inclusion-list native journeys. Publication, installation and product acceptance are distinct. Missing publisher auth, console access or required native proof is BLOCKED/NOT RUN, never PASS. Match actual target/effects to authority.
8. **Record and close out.** Save source/inclusions/targets/artifact/delivery/native proof, limits and owners in existing release/task/public records. Reconcile feature source integration and delivered version separately; retain specific gaps under the responsible release/product task. Retire eligible worktrees through Norml Git. No feature chat/checkout remains a release queue. Report **published; acceptance incomplete** when that is the result.

Minimum inclusion record: previous version/revision, frozen candidate, every included PR/direct commit/task, risks/compatibility/migrations/journeys, combined and real-package results, reuse-equivalence basis, blockers/limits/owner and target/artifact outcome. Use the established task/evidence, not a second service or queue.

Exit: the selected target's actual acceptance only. TASK-024 normal-workload freezing acceptance and Marketplace access do not close from a source/pipeline check. Progress preserves this stage's eight steps and completed parent history without importing unrelated deployment obligations.
